## Directory Purposes

**BotecoRate/ (root):**

- Purpose: Project root; entry point files and configuration
- Contains: App.js (root component), index.js (entry), app.json (Expo config), package.json (dependencies)
- Key files: `App.js` is the navigation coordinator; `app.json` defines permissions and plugins required for camera, location, biometric auth

**src/:**

- Purpose: All application source code
- Contains: Organized subdirectories for screens, services, utilities, data
- This is the only directory that changes during development (apart from assets)

**src/screens/:**

- Purpose: One screen component per user-facing page or route
- Contains: React Native screen components (SafeAreaView, ScrollView, FlatList, forms, etc.)
- Naming: `Tela[Name].js` (Portuguese "Tela" = "Screen")
- Key files:
  - `TelaLogin.js`: Authentication entry point
  - `TelaListagemBares.js`: Main app feed and local sub-navigation hub (most complex screen)
  - `TelaDetalhesBar.js`: Bar details, ratings, menu items
  - `TelaMapaGPS.js`: Map display (location permission + marker rendering)

**src/services/:**

- Purpose: AsyncStorage persistence layer
- Contains: Simple read/write functions for bars and users
- Key files:
  - `storage.js`: Whole-list read/write for bars (`@boteco_rate_bares` key)
  - `authStorage.js`: Whole-list read/write for users (`@boteco_rate_usuarios` key) + session management (`@boteco_rate_sessao` key)
- Pattern: All functions are `async`; they catch errors internally and return fallback values (null or [])

**src/utils/:**

- Purpose: Pure calculation and formatting functions
- Contains: Stateless utility functions with no side effects
- Key files:
  - `nota.js`: Average rating calculation
  - `distancia.js`: Haversine formula for distance + formatting
  - `data.js`: Date/time formatting
  - `senha.js`: Password validation rules

**src/data/:**

- Purpose: Seed/initial data for first app launch
- Contains: Mock bar objects with complete schema
- Key files:
  - `mockBares.js`: `baresIniciais` array exported; used when AsyncStorage is empty

**assets/:**

- Purpose: Static images and icons
- Contains: PNG files for app icon and splash screen
- Used by: `app.json` references these for splash and adaptive icon

**docs/:**

- Purpose: Project documentation (if any)
- Not part of active source code

**.planning/codebase/:**

- Purpose: Codebase analysis documents (generated by `/gsd-map-codebase`)
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md
- Not committed to git (in `.gitignore`)

## Naming Conventions

**Files:**

- Screen files: `Tela[Purpose].js` (e.g., `TelaLogin.js`, `TelaDetalhesBar.js`)
  - Always PascalCase
  - Always start with `Tela` (Portuguese for "Screen")
  - No hyphens or underscores
- Service files: `[domain].js` (e.g., `storage.js`, `authStorage.js`)
  - camelCase
- Utility files: `[feature].js` (e.g., `nota.js`, `distancia.js`)
  - camelCase
- Data files: `mock[Entity].js` (e.g., `mockBares.js`)
  - Prefix with `mock` to indicate seed data

**Directories:**

- All lowercase: `src/screens/`, `src/services/`, `src/utils/`, `src/data/`
- Plural for collections: `screens`, `services`, `utils` (not `screen`, `service`, `util`)

**Functions:**

- camelCase: `carregarBares()`, `salvarBares()`, `calcularNotaMedia()`, `validarSenha()`
- Export as named functions, not default exports (except screen components, which are default exports)

**Variables & State:**

- camelCase: `bares`, `barSelecionadoId`, `usuarioLogado`, `mensagemBoasVindas`
- State getter/setter: `const [state, setState] = useState(initial)` (React convention)

**Constants:**

- UPPER_CASE: `STORAGE_KEY`, `USUARIOS_KEY`, `SESSAO_KEY`, `MEDALHAS`
- Defined at module top level

**Styling:**

- Inline StyleSheet objects: `StyleSheet.create({ ... })` defined at bottom of each screen file
- Naming: `styles.containerName`, `styles.buttonText`, `styles.inputField`, etc. (camelCase for style names)

## Where to Add New Code

**New Screen (e.g., Feature X):**

1. Create `src/screens/TelaNomeFeature.js`
2. Export as default: `export default function TelaNomeFeature({ ...props }) { ... }`
3. Import necessary React Native components, services, utilities
4. Handle local state with `useState()` for any screen-specific data
5. Add callback props for navigation (e.g., `onVoltar`, `onSomething`)
6. Register in `App.js`:
   - Add state option to `tela` state (line 12 comment: `// 'login' | 'cadastroUsuario' | ...`)
   - Add conditional render: `{tela === 'newFeature' && <TelaNomeFeature ... />}`
   - Wire up navigation callbacks in appropriate parent screen

**New Service Function (e.g., Persist Feature X Data):**

1. Add to appropriate service file (`storage.js` or `authStorage.js`)
2. Use AsyncStorage key pattern: `@boteco_rate_[domain]`
3. Always wrap in try-catch; log errors; return fallback on error
4. Export as named function: `export async function carregarFeatureData() { ... }`
5. Pattern to follow: `carregarBares()` in `storage.js` (lines 5-18)

**New Utility Function (e.g., Calculation or Formatter):**

1. Create or add to appropriate file in `src/utils/`
2. Make it a pure function (no side effects, no state)
3. Export as named function: `export function nomeUtilidade(param) { ... }`
4. Add JSDoc comment if complex
5. Pattern to follow: `calcularNotaMedia()` in `nota.js`

**New Seed Data (e.g., More Mock Bars):**

1. Edit `src/data/mockBares.js`
2. Add object to `baresIniciais` array
3. Match schema: `{ id, nome, endereco, foto, latitude, longitude, avaliacoes, detalhes, cardapio, criadoPor }`
4. Ensure all required fields are present (see full example in `mockBares.js` lines 1–50+)

**New Styles:**

- Keep StyleSheet with the screen component (inline at bottom)
- No separate CSS or stylesheet files
- Use React Native `StyleSheet.create()` for optimization
